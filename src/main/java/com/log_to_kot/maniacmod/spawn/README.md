# spawn — розкидання по карті

Карта 300 × 300 блоків із заздалегідь розміченими точками.

## Файли

- `SpawnPointKind` — SURVIVOR / MANIAC / ITEM / GENERATOR / EXIT
- `SpawnPoint` — одна точка: позиція, поворот, вид, власник
- `SpawnRules` — усі числа в одному місці
- `SpawnPlanner` — будує план розкидання

## Правила

| Правило | Значення | Послаблюється? |
|---|---|---|
| Одна точка = один гравець | — | **ніколи** |
| Виживий ↔ маньяк | ≥ 60 бл | так, до 6 кроків по ×0.85 |
| Виживий ↔ виживий | ≥ 20 бл | так, аналогічно |
| Задіяних ITEM-точок | ≈ 60% | — |

Точки маньяка прив'язані до `ownerId` — id архетипу. У Чакі і
Слендермена різні стартові локації.

## Як точка стає генератором у світі

1. Адмін ставить точку: `/maniac point add generator` (зберігається у
   `points.yml`, ключ `generatorPoints`).
2. `SpawnPlanner.pickGeneratorPoints` обирає з них підмножину через
   `GeneratorPointSelector`: випадковий порядок + відстані між
   генераторами та до маньяка (`minGeneratorToGeneratorBlocks`,
   `minGeneratorToManiacBlocks`), які послаблюються покроково, лише
   якщо розмітка не дозволяє їх дотримати. Усі допустимі набори
   досяжні (старий «найдальша від обраних» давав майже той самий набір
   щоразу).
   **Скільки точок треба МІНІМУМ** — `generatorsRequired` +
   `bonusGeneratorsPerManiac` × кількість маньяків (за замовчуванням
   6 + 1×1 = **7**). Точок менше — план не будується.
3. `MatchOrchestrator.applySpawnPlan` (фаза `SCATTER`) для кожної
   обраної точки додає логічний запис `GeneratorPoi`, а потім
   `GeneratorEntity.spawn(...)` — сутність-тіло.
4. `GeneratorEntity.spawn` МУСИТЬ викликати `level.addFreshEntity`.
   `MatchRuntimeRegistry.register` лише ставить NBT-маркер для
   очищення й у світ нічого не додає.

**Що бачить адмін, коли не вистачає точок генераторів:**
- звичайний режим — матч не стартує, команда пише причину
  («Потрібно щонайменше 7 точок генераторів … а налаштовано 3»);
- `debugMode` — матч усе одно стартує й бере СТІЛЬКИ генераторів,
  скільки реально розмічено (навіть 0), замість того щоб відмовляти у
  всьому плані. Кількість виживих на це не впливає: одиночний тест
  «я маньяк, виживих немає» отримує ті самі генератори й той самий
  лут, що звичайний матч — за умови, що самі точки розмічені.
  Порожній план (`SpawnPlan.empty()`, без телепорту й без нічого)
  лишається лише для випадку, коли на карті взагалі немає жодної
  точки (`allPoints` порожній) — тоді план будувати нема з чого, і
  причина йде в чат червоним `[debug]`.

Для тестів із малою кількістю точок не додавай фіктивні, а зменшуй
`generatorsRequired` і `bonusGeneratorsPerManiac` у `generators.yml`
(наприклад 2 і 0 — рівно 2 генератори), або просто розмічай менше й
поклад на дебаг-толерантність вище.

Сутність-сирота (залишок минулого матчу чи краху, ожила при завантаженні
чанка) сама себе знищує на першому тіку, якщо для її позиції немає
`GeneratorPoi` у поточному матчі.

## Порядок

1. `plan(...)` рахує все в пам'яті.
2. Не вдалося — `SpawnPlanFailure`, **нікого ще не зрушено**.
3. Вдалося — застосовуємо план і телепортуємо.

Інверсія цього порядку і була джерелом «половина команди на карті,
половина в лобі».

## Ще не зроблено

- Команди розмітки (`/maniac addpoint …`) і збереження у конфіг світу
- Валідація, що точка всередині 300×300 (`SpawnPlanner.isInsideMap`)
- Перевірка, що під точкою тверда поверхня
