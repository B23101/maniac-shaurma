# config — налаштування

**Головний конфіг** — `<світ>/maniacmod/maniac.yml` (блок `game`:
мінімум гравців, тривалості технічних фаз, дебаг-режим). Дефолт лежить у
jar за `/config/maniacmod/maniac.yml`.

**Другорядні** — кожен у своєму файлі тієї ж теки: `world.yml`,
`survivors.yml`, `maniacs.yml`, `generators.yml`, `points.yml`,
`inventory.yml`. Розділення навмисне: головне редагується часто, решта —
рідко, і разом вони давали б один файл на кількасот рядків.

## Файли

- `ConfigKey` — один ключ: шлях, тип, дефолт, діапазон
- `ConfigBlock` — блок верхнього рівня, SETTINGS або DATA
- `ConfigSchema` — уся схема, єдине джерело правди
- `ConfigDiagnostics` — список зауважень за один прохід
- `ManiacConfigs` — завантаження, лікування, валідація, reload

## Читання

```java
int required = ManiacConfigs.get(ConfigSchema.GENERATORS_REQUIRED);
```

Ключ — об'єкт, тому прочитати неоголошене неможливо. Значення
завжди валідне: діапазон перевіряється при читанні файлу.

**Не копіюй значення в поле.** Гетер читає мапу в пам'яті, це дешево.
Скопійоване в поле число — і є та сама причина, чому частина
налаштувань «підхоплюється лише після рестарту».

Якщо модулю потрібно перебудувати щось похідне — підписка:

```java
ManiacConfigs.reloadBus().subscribe(modeId -> rebuildSomething());
```

Бус спрацьовує **після** підміни снапшоту, тож у обробнику вже нові
значення.

## Дебаг-режим

Для перевірок наодинці (один гравець, без карти/точок):

```yaml
game:
  debugMode: true
  debugRole: SURVIVOR   # або MANIAC / AUTO
```

- матч стартує з **одним** гравцем (мінімум гравців ігнорується):
  `/maniac start` — і ти в грі;
- `debugRole` вирішує, ким буде цей гравець:
  - `MANIAC` — ти маньяк, **виживих немає взагалі** (маньяк = виконавець
    команди або нік з `/maniac start <нік>`);
  - `SURVIVOR` — ти виживий, **маньяка немає взагалі** (слоти, стаміна,
    генератори, лут — усе, що не залежить від маньяка); реєстр маньяків
    при цьому може бути порожній;
  - `AUTO` — звичайний вибір маньяка, як на живому сервері;
- план розкидання може бути **недоступним** (немає точок/карти) — матч
  усе одно стартує, просто без телепорту й генераторів;
- матч **не завершується**, коли з будь-якого боку лишається 0 гравців —
  тобто можна дожити до кінця механіки, не викидаючи себе в ENDING.

## Перезавантаження

Три шляхи, усі дають однаковий результат:

1. Змінив файл — підхопиться протягом секунди (перевірка mtime у
   серверному тіку).
2. `/maniac reload` — те саме плюс повний список зауважень у чат.
3. Старт сервера.

## Мертві налаштування

Ключ у файлі, якого немає в схемі, потрапляє в лог як «ні на що не
впливає». Те саме для цілого блока. Мод нічого не видаляє — лише
каже.

## Неможливі налаштування

Діапазон оголошений поруч із дефолтом, значення поза ним підтягується
до межі з попередженням. Переліки (`playerMode`, `typeMode`, `debugRole`)
закриті: чужий рядок відкочується до дефолту.

Те, що фізично не може бути іншим, у конфіг не виноситься взагалі:

| Не налаштування | Чому |
|---|---|
| 3 здібності маньяка | клавіші 1/2/3 — четверту нема на що повісити |
| 3 слоти пасток | клавіші Z/X/C |
| 0 слотів інвентаря маньяка | у маньяка немає інвентаря, звідси й вільні цифри |
| тривалість кінематики | самої кінематики ще немає — фаза пропускається в коді |

## Лікування: тільки блоками

Мод оновився, з'явився новий блок → блок дописується в кінець файлу з
дефолту в jar.

Блок є, але всередині чогось бракує → **нічого не дописується**,
відсутній ключ просто читається з дефолту в пам'яті.

Причина конкретна. Адмін, який видалив дві точки зі списку, не має
отримувати їх назад щостарту. Наявність блока означає «людина цей
розділ бачила»; відсутність — «розділ новий, покажи його».

Дописування йде **текстом у кінець файлу**, а не перезаписом
розпарсеного дерева — інакше з файлу зникли б коментарі адміна.

## DATA-блоки

`spawn_points` і `zones` наповнюють команди. Ключі в них не
валідуються (склад заздалегідь невідомий) і вміст не відновлюється
ніколи.

## Додати налаштування

1. Константа `ConfigKey` у `ConfigSchema`.
2. Додати її в список відповідного `ConfigBlock`.
3. Дописати рядок у `src/main/resources/config/maniacmod/<файл блока>`.

Крок 3 потрібен лише для нових БЛОКІВ — без нього новий блок не буде
чим лікувати. Новий ключ усередині наявного блока працює й без нього,
на дефолті.
