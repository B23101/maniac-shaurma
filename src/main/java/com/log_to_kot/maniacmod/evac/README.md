# evac/ — евакуація після генераторів

Генератори готові → приймач → виклик → ракета на галявині → вертоліт → мотузка → лазіння → відліт.

## Потік

```
HUNT ─(генератори)→ POWERED ─(виклик з приймача)→ HELI_WAIT ─(мотузка спущена)→ FINALE ─(відліт)→ ENDING
                     DORMANT      WAIT_FLARE → DISPATCH → INBOUND → DESCEND → ROPE_DROP     HOVER → ROPE_RETRACT → DEPART → DONE
```

Фазами керує `MatchOrchestrator.checkPhaseExitConditions` за досягненнями
(`HELI_CALLED`, `EXIT_OPENED` = мотузка готова); `EvacModule` лише ставить досягнення.
Стадії (`EvacStage`) — дрібна механіка вертольота, назовні не видна.

## Правила

| Що | Правило |
|---|---|
| Приймач | Один на матч. Точок (`/maniac point add receiver`) — скільки завгодно, береться одна випадкова, не ближче `receiverMinManiacBlocks` до маньяка. Поворот: yaw адмінa в момент команди → `ReceiverEntity.rotationX`, нахил завжди 0 |
| Меню | ПКМ по приймачу (лише виживі, ≤ `receiverUseDistanceBlocks`). Кнопка «Викликати вертоліт» активна лише в `POWERED` |
| Ракета | Предмет `signal_flare`, `flareCount` штук на різних ITEM-точках. ПКМ: після виклику, на землі, у повній галявині. Невдача ракету НЕ витрачає |
| Галявина | Два кути (діагональ) + точка вертольота всередині. Висота кутів не важить. Зона позначається суцільними плоскими жовтими квадратами на верхній грані кожного блока (без рамок; землю клієнт шукає сам, спускаючись колонкою від `MOTION_BLOCKING` повз листя/траву), видно виживим завжди, коли сервер надіслав розмітку — ракету тримати не обов'язково (`ClearingZoneRenderer`). Розмітка шлеться виживим на вході в HUNT і повторно раз на 5 с, поки ракета не запущена |
| Політ | Вертоліт НЕ падає з неба над галявиною. Через `heliDispatchDelaySeconds` він з'являється за `heliSpawnDistanceBlocks` (400) блоків від точки зависання й летить до неї прямою; напрям — у бік `heli entry`, а без неї — найвільніший із 8 напрямків. Висота на кожному метрі шляху береться з **профілю** (див. нижче), наприкінці він плавно гальмує й висить на `ropeLengthBlocks` над землею |
| Профіль висот | `EvacModule.buildProfile`. Уздовж шляху (крок 3 бл.) у смузі ±5 бл. беремо найвищий блок (`MOTION_BLOCKING`: дерева, будівлі), додаємо запас (біля галявини 6 бл., далі плавно до `heliCruiseClearanceBlocks`) і «розтягуємо» вимогу на розмах гвинта (5 бл.) з обмеженою крутизною (`heliDescendBlocksPerSecond / heliSpeed`). Виходить пологий схил над будь-яким рельєфом. Відліт летить тим самим профілем у зворотний бік — тож ні приліт, ні відліт не зачіпають блоків. Висота зависання піднімається над кронами/дахом, якщо вони над точкою (мотузка тоді довша за конфіг) |
| Чанки | Коридор 400 бл. підвантажується квитками чанків (`TicketType`, тайм-аут 20 с, оновлення раз на 5 с, на диск нічого не пишеться; сутності вертольота й мотузки `shouldBeSaved = false`). Позиція вертольота «віртуальна» (поля модуля), сутність лише слідує за нею — відсутній чанк не може зупинити стадії |
| Мотузка | Розмотується `ropeDropSeconds`; клікабельна лише розмотана повністю. Нижній кінець висить на 0.5 блока над землею (`EvacRopeEntity.GROUND_CLEARANCE`) і гойдається: клієнтський ланцюжок Верле (`EvacRopePhysics`) — гравітація, потік від гвинта, прогин до того, хто лізе. Чиста косметика, без пакетів |
| Лазіння | ПКМ по мотузці → гравець пасажир `ClimbCarrierEntity`, їде вгору `climbBlocksPerSecond`. Їде НЕ по осі мотузки, а збоку (`CLIMB_SIDE_OFFSET` = 0.8 бл., зі сторони, звідки підійшов) і дивиться на неї — камера не опиняється всередині мотузки. Долізла до верху → `ESCAPED` (глядач) |
| Удар маньяка | Без нокауту — лізе далі (опційна пауза `climbHitStaggerTicks`). Нокаут → падає непритомним з реальної висоти, лізти не може, поки не підніме союзник |
| Зіскочити | Shift. Падіння з реальної висоти (`fallDistance` виставляється явно) |
| Втеча | Долізла до верху → `ESCAPED`, глядач-камера біля вертольота, усім action-bar «Ім'я втік! 3/6» (`announceEscape`; «усього» = втекли + вибули + ще в грі) |
| Перемога | `MatchOrchestrator.survivorsWon()` — єдине правило: втік хоча б один → виживі, ніхто → маньяк. Матч завершується (ENDING), коли живих, що не втекли, нуль, або вертоліт відлетів. Результат шле `MatchOutcomePacket` перед фазою ENDING; екран підсумків показує банер |
| Відліт | Починається, коли вийшов `heliStaySeconds` (90 с від готовності мотузки; пільга для тих, хто вже лізе, — `departGraceSeconds`, за замовчуванням 0) **або коли лізти вже нікому** (усі втекли/вибули/лежать без сил; пауза 3 с). Порядок: (1) `ROPE_RETRACT` — мотузка підтягується вгору за `ropeDropSeconds`, **хапатися вже не можна** (клік відхиляє сервер, мотузка не pickable з першого тіку); хто ще на мотузці — падає; (2) `DEPART` — розворот на місці й виліт по профілю з розгоном; (3) на 300 бл. від точки вертоліт зникає → `DONE` → `ENDING` |
| «Усі втекли» | Коли втік останній, `noSurvivorsLeft()` переводить матч у `ENDING` ОДРАЗУ. `EvacModule` тікає й у `ENDING` (лише довершити відліт: мотузка → виліт), а оркестратор не скидає матч у `RESET`, поки `evac.isDeparting()` (запобіжник +40 с). Раніше модуль у `ENDING` не тікав — вертоліт завмирав у повітрі, а `RESET` його прибирав |

## Tab: як змінюється завдання

| Фаза / крок | Заголовок (виживий) | Модель у картці | Підказка |
|---|---|---|---|
| `HUNT` | Полагодь генератори | генератор | слоти = генератори |
| `POWERED` | Знайди приймач | приймач | відстань, якщо він у завантаженій зоні |
| `HELI_WAIT`, ракети в мене нема | Знайди сигнальну ракету | ракета (`signal_flare.geo.json`) | відстань і напрям до галявини |
| `HELI_WAIT`, ракета в інвентарі | Запусти ракету на галявині | ракета | те саме |
| ракету запущено (`FLARE_FIRED` або крок ≥ INBOUND) | Вертоліт летить | вертоліт | на `ROPE_DROP` — «спускає мотузку» |
| `FINALE` | Лізь по мотузці | вертоліт | секунди до відльоту |

У евакуації слоти — чотири кроки: світло → виклик → ракета → мотузка. Крок бере `TabObjectiveCard.mode()`
з фази, `ObjectiveSyncPacket` і `ClientEvac.step()`; клієнт нічого не вирішує, лише показує.

## Старий вихід через EscapeZone

Прибрано: правило `ESCAPE` більше не діє в `POWERED`, а `SurvivorModule.tickEscapes` (втеча входом
у зону) видалено — єдиний вихід тепер мотузка вертольота. Зони `EscapeZoneArchetype` лишились у
розмітці, але нічого не роблять.

## Захист від soft-lock

* `flareWatchdogSeconds`: якщо ракет не лишилось ні на землі, ні в інвентарях — нова біля приймача.
* Сутність вертольота/мотузки зникла (вигрузка чанка, команда) — створюється заново там, де модуль її «тримає» (лише в завантаженому чанку); стадії від цього не зупиняються.
* Гравець вийшов із сервера на мотузці — знімається з носія до того, як lib залишить тіло.
* Сироти (залишки минулого матчу) самознищуються: кожна сутність питає `evac().owns…()`.

## Розмітка (команди)

```
/maniac point add receiver          стань, де має стояти приймач, і ДИВИСЬ туди, куди він має «дивитись»
/maniac clearing create <n>
/maniac clearing corner <n>         двічі, у протилежних кутах
/maniac clearing heli <n>           точка зависання (всередині прямокутника; Y не важить)
/maniac clearing list|reset|remove|clear
/maniac heli entry [clear]          у який бік від галявини лежить місце появи (дистанція — heliSpawnDistanceBlocks;
                                    без точки напрям обирається автоматично — найвільніший із 8)
/maniac generators complete         дебаг: одразу POWERED
```

Галявини зберігаються в `zones.yml` (ключі `clearings`, `heliEntry`), приймачі — в `points.yml`
(`receiverPoints`). Налаштування — `evacuation.yml`.

## Інтерфейс (клієнт)

| Що | Клас | Дані |
|---|---|---|
| Панель кроку + лічильник «втекло N/M» + шкала часу до відльоту | `client/evac/EvacHudOverlay` | `EvacStatusPacket` (крок, втекли, всього, секунди) — раз на секунду й на кожну зміну |
| Банер «Ім'я втік! 3/6» (кільце-лічильник, промінь, відскок) | `EscapeToastOverlay` | `EscapeAnnouncePacket` |
| Підказки над прицілом: приймач (3 стани), мотузка; під час лазіння — вертикальна шкала висоти + «Shift — зіскочити» | `EvacHintOverlay` | приціл, фаза, `ClientEvac` |
| Меню приймача: радіохвилі, ланцюжок 4 кроків, «дихаюча» кнопка | `ReceiverMenuScreen` | `ReceiverMenuOpenPacket` + `ClientEvac.step()` |

Клієнт нічого не вирішує: усе — з сервера (`EvacModule.statusPacket()`). Таймер між пакетами
плавно йде на клієнті (`ClientEvac.secondsLeft()`). Пакети додано в кінець блоку `ModNetwork`.

## Що НЕ зроблено (потрібен арт / рішення)

* Моделі `receiver`, `helicopter` — **заглушки з кубів** (є рух і анімації `off/ready/called`, `fly`).
* Анімація лазіння — **тимчасова** (`player_animation/climb_rope.json`) — замінити авторською.
* Звуки: гвинт зараз — ванільний `WARDEN_HEARTBEAT` низьким тоном (`EvacModule.tickRotorSound`),
  ракета — ванільний `FIREWORK_ROCKET_LAUNCH`. Власні `.ogg` (гвинт-луп, рація, «втік») — підкласти в
  `ModSounds` і замінити виклики.

## Голос диспетчера (після виклику з приймача)

`EvacModule.onReceiverCall` → `DispatcherPacket(CALL)` усім (маньяку — за `EVAC_ANNOUNCE_TO_MANIAC`).
Клієнт (`client/evac/ClientDispatcher` + `DispatcherOverlay`) грає репліки як звук БЕЗ позиції й
одночасно «друкує» текст у панелі-рації. Старт кожної репліки — один годинник для звуку й тексту,
довжина береться з самого `.ogg` (`OggSoundLength`), тож заміна запису нічого не ламає.

| Що | Де |
|---|---|
| Тексти | lang: `maniacmod.evac.dispatcher.call.1..3` |
| Голос | `sounds/dispatcher_call_1..3.ogg` (зараз — ЗАГЛУШКИ-радіошум, замінити записом) |
| Тріск каналу | `sounds/dispatcher_open.ogg`, `dispatcher_close.ogg` (необов'язкові) |
| Новий сценарій | елемент у `ClientDispatcher.SCRIPTS` + константа в `DispatcherPacket` + виклик `dispatcherSay(n)` |
