# client — клієнтська частина

## Файли верхнього рівня

- `ManiacKeybinds` — клавіші
- `ClientInputHandler` — натискання → C2S-пакети
- `ClientMatchState` — дзеркало стану матчу
- `ClientPacketHandler` — єдина точка, куди пишуть S2C-пакети
- `ClientSetup` — реєстрація рендерерів і оверлеїв
- `overlay/` — оверлеї поверх геймплею, БЕЗ перехоплення вводу (нижче)
- `screen/` — повноцінні меню з перехопленням вводу (нижче)
- `renderer/` — рендерери сутностей у світі

## Потік

```
сервер → S2C-пакет → ClientPacketHandler → ClientMatchState
                                                 ↓
                                         overlay / screen
```

```
клавіша → ClientInputHandler → C2S-пакет → сервер
```

Клієнт нічого не рахує сам. Хп, стаміна, кулдауни, стани генераторів,
ростер гравців приходять із сервера. Локально відлічується тільки час
(кулдаун здібності, згасання підсвітки) — щоб не тримати потік
пакетів.

## `overlay/` — за ЗМІСТОМ, тим самим принципом, що й `net/s2c/`

Малюється поверх геймплею, не перехоплює ввід. Категорія — за тим,
ЩО показується, не за тим, ДЕ на екрані воно опиниться (та сама
причина, що й у `net/README.md`: якщо називати за місцем виводу,
туди рано чи пізно почне падати випадкова інформація).

| Категорія | Що це | Джерело | Статус |
|---|---|---|---|
| `actionprogress/` | прогрес дії, що триває (бар ремонту) | `s2c/actionprogress/*` | є — `GeneratorProgressOverlay` |
| `vitals/` | постійний HUD власних показників (хп/стаміна) | `s2c/vitals/SurvivorVitalsPacket` | план, див. `vitals/README.md` |
| `effects/` | повноекранні ефекти за станом (серцебиття, непритомність) | `ClientMatchState` (не новий пакет) | план, див. `effects/README.md` |
| `notify/` | одноразові повідомлення | `s2c/notify/*` | вже реалізовано в shaurma-lib, НЕ тут — див. `notify/README.md` |
| `roster/` | таб-список гравців | `s2c/matchstate/RosterSyncPacket` | план, див. `roster/README.md` |

## `screen/` — повноцінні меню, гравець явно взаємодіє

| Категорія | Що це | Статус |
|---|---|---|
| `maniac/` | вибір архетипу маньяка | план, див. `maniac/README.md` |
| `admin/` | GUI-еквівалент `/maniac` команд | план, див. `admin/README.md` |
| `statistics/` | підсумки матчу | план, див. `statistics/README.md` |
| `minigames/` | QTE ремонту/дій (дизайн не затверджено) | план, див. `minigames/README.md` |

Кожна порожня категорія має власний README із планом — так само, як
`net/s2c/matchstate/RosterSyncPacket` раніше жив планом у
`net/s2c/roster/README.md` до реалізації. Мета — щоб той, хто (людина
чи ШІ) почне писати конкретний екран, одразу знав, звідки брати
дані, і не винаходив новий пакет для того, що вже летить.

## Клавіші

| Дія | Клавіша | Звідки |
|---|---|---|
| Здібність | E | власна |
| Підсвітка генераторів | 5 | власна |
| Підвестися | пробіл | ванільна (jump) |
| Підняти непритомного | Shift | ванільна (sneak) |
| Ремонт / підбір | ПКМ | ванільна (use) |

Пробіл і Shift — навмисно ванільні: гравець, що перепризначив
стрибок, не має отримати дві різні клавіші для «стрибнути» й
«встати».

Клавіша 5 вільна, бо в інвентарі виживого 4 слоти. Формальний
конфлікт із `key.hotbar.5` нешкідливий — `InventorySlotAllocation`
не дає вибрати заборонений слот.

## Скидання стану

`ClientMatchState.reset()` викликається при переході у `LOBBY`/`RESET`.
Кожен новий клієнтський стан має скидатись саме там — у v3 оверлеї
тримали власні статичні поля, які ніхто не чистив, і бар ремонту
лишався висіти після завершення матчу. Кожен новий клас у `overlay/`
чи `screen/`, що тримає власний стан, реєструє своє скидання тут же,
за зразком `actionprogress/GeneratorProgressOverlay.reset()`.
