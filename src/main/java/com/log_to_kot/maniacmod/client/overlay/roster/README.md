# client/overlay/roster — tab-екран

## Статус: повністю переписано (приладова панель матчу)

Утримання ванільної Tab (через `dev.shaurmalib.forge.tab.TabVisibilityModule`,
підключений у `ClientSetup`) показує не плоский список, а панель з картками.
Вигляд — `client/style/ManiacTabTheme`, підключена до бібліотечного
`TabListStyle` другим аргументом конструктора.

## Файли

| Файл | Що робить |
|---|---|
| `TabRosterOverlay` | Оркестратор: збирає `TabContext`, розкладка, вступна/вихідна хореографія, іскри |
| `TabContext` | Зріз кадру: час, гравці, розбиті на групи (маньяк / живі / вибули / глядачі) |
| `TabObjectiveCard` | Верхня картка: 3D-генератор, завдання (від ролі й фази), «N / M», слоти, віхи |
| `TabManiacCard` | 3D-маньяк у кривавому серпанку; при 2+ маньяках плавно перемикається між ними (затемнення + зсув, крапки-індикатор) |
| `TabSideCards` | «ТИ» (3D + хп + ЕКГ) для виживого, «ЗВЕДЕННЯ» для маньяка/глядача |
| `TabSurvivorList` | Секції ВИЖИВШІ / ВИБУЛИ / ГЛЯДАЧІ, рядки з хп-привидом і таймером лежачого |
| `TabModel3d` | Малює справжніх гравців («ТИ») у GUI |
| `TabGeoView` | Малює geo-моделі маньяка й генератора напряму з ассетів, БЕЗ сутностей у світі |
| `TabFx` | Безстанові помічники: текст із масштабом, «розшифровка», штриховка |
| `TabIcons` | Піксельні іконки (стани, віхи, зведення) — бітові мапи, без текстур |

## Джерела даних (клієнт нічого не рахує)

- `ClientMatchState.roster()` ← `RosterSyncPacket` — хто є хто, хп, стан
- `ClientMatchState.objectives()` ← `ObjectiveSyncPacket` — скільки генераторів, віхи
- `ClientMatchState.downedEntries()` ← `DownedSurvivorsPacket` — таймери лежачих

## Завдання за роллю й фазою

Ключі `maniacmod.tab.objective.<role>.<phase>` (+ `.sub`) у lang. Нова фаза
в `GamePhase` без запису тут покаже «Очікування матчу» — додай три ключі.

## Секрет маньяка

Хто маньяк і який архетип — знає лише сам маньяк. Для виживих і глядачів картки маньяка в Tab
немає взагалі (`TabContext.maniacHidden` → `maniacs` порожній, `TabRosterOverlay` її не малює; ліва колонка — лише «ТИ»/«ЗВЕДЕННЯ»).
Не повертай ім'я/архетип маньяка в інші місця Tab (рядки списку, зведення) для не-маньяків.
Примітка: `RosterSyncPacket` досі їде всім разом із записом маньяка (потрібен світу: хітбокс/модель),
тож це приховування на рівні UI; повне приховування на рівні пакета — окрема задача.

## Заборонено

Не запитувати в `RosterSyncPacket` stamina/heartbeat. Не рахувати «скільки
генераторів» на клієнті (лічильник із сервера — єдине джерело).

## Правила показу

- Звуків появи/закриття немає. Звук лишився лише на завершення генератора й тривогу в списку.
- Генератори: жодних відсотків, бензину чи стану «у роботі». Слот порожній, доки генератор не полагоджено повністю; тоді загоряється (лічильник «1 / 6»).
- Маньяк: «втекли» видно лише у фазі, що дозволяє втечу (`PhaseRule.ESCAPE`); серед вибулих — лише його жертви
  (`RosterEntry.killerId`, сервер пише «хто вдарив останнім» у `MatchContext.recordManiacHit`).

- Стан гравця пишемо лише коли він щось означає (`TabSurvivorList.worthShowing`): «Здоровий» не виводиться ні в списку, ні в картці «ТИ» — це норма, її видно з хп-шкали.
- Віхи матчу — по ролі (`TabObjectiveCard.milestoneRelevant`): виживий бачить живлення й вихід; маньяк — першу кров, живлення, вихід (+ «втеча» лише у фазі втечі); глядач — усі.
- Іконки стану/віх/зведення — `TabIcons`; нова іконка = нова бітова мапа в enum, жодних ассетів.

## 3D

Моделі малюються лише коли панель розгорнута повністю. Маньяк і генератор малюються через `TabGeoView` (власний geo-рендер, не залежить від сутностей). Якщо хоч один
рендер кине виняток, `TabModel3d`/`TabGeoView` вимикають 3D до перезапуску гри — Tab
лишається робочим, картки переходять на плоский фолбек (голови/іконки).
