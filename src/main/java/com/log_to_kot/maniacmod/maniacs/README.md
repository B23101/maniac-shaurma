# maniacs/ — маньяки

## Що тут

- **ManiacArchetype** — абстрактний базовий клас. Дані, які задає
  код (габарити, очі, асе́ти), дефолти балансу
  (`declaredAttackDamage()` тощо) і спільна логіка лежать тут ОДИН раз.
- **ManiacRegistry** — список усіх маньяків гри. Єдине місце
  реєстрації; воно ж оголошує блок конфігу кожного маньяка.
- **TestManiacArchetype** — шаблон, на якому відпрацьована вся
  технологія (хітбокс, очі, гео-модель, анімації). Конкретний маньяк
  лише передає свої числа в конструктор базового класу і перевизначає
  `weaponItem()` / `abilities()` / `traps()`. Жодної логіки
  атаки/спавну тут немає — вона в `ManiacArchetype` або в
  `MatchOrchestrator` (диригент матчу).

## Налаштування маньяка — окремий файл на кожного

Баланс (габарити, висота очей, дальність удару, шкода, перезарядка,
множник швидкості) живе НЕ в класі, а в
`config/maniacmod/maniac_stats/<id>.yml`. Файл створюється сам із
дефолтів класу при першій реєстрації, а далі правиться без
перекомпіляції — і стосується лише свого маньяка. Спільного ключа
«на всіх» немає навмисно: правити одного маньяка не означає чіпати
решту. Див. `config/ManiacStats`.

## Як додати нового маньяка

1. Новий файл `PennywiseArchetype.java` у цьому пакеті,
   `extends ManiacArchetype`.
2. Асе́ти під його id: `pennywise.geo.json`, `pennywise.animation.json`,
   `pennywise.png`.
3. Один рядок `register(new PennywiseArchetype());` у
   `ManiacRegistry`.

Все — конфіг (`maniacTypeMode: RANDOM/FIXED`), меню вибору
персонажа, команда `/maniac settype` і файл його власних параметрів
автоматично побачать нового маньяка, бо вони читають список через
`ManiacRegistry.all()`, а не через hardcoded enum (як було у v3
`entity/ManiacType`).

## Здібності маньяків — див. `abilities/`

Активні здібності (ривок, телепорт, невидимість тощо) — НЕ методи
всередині Archetype-підкласу, а окремі класи в `abilities/`, які
Archetype лише підключає списком у `abilities()`. Це дозволяє
перевикористати одну й ту саму здібність між кількома маньяками
без копіювання коду.
