# server — серверна частина

## Файли

- `ServerHooks` — міст між подіями Forge і матчем
- `ServerPacketHandler` — перевірка намірів клієнта
- `ManiacCommand` — `/maniac`

## ServerHooks навмисно короткий

Він лише переадресовує:

```java
match.tick(players);   // весь серверний тік
```

Жодних перевірок фази, жодних ручних викликів механік. Модулі
реагують на фази у своїх `PhaseListener`-ах.

v3-еквівалент (`ServerEventHandler`, 162 рядки) робив усе сам: тікав
пастки, синхронізував кулдаун, перевіряв ремонт і втечу, міняв
хітбокс. Кожна нова механіка дописувала туди ще кілька рядків.

## Перевірки в ServerPacketHandler

Однакова форма в кожному методі: матч → роль → дозвіл фази → стан.
Клієнтські перевірки не рахуються — клієнт може бути модифікований.

## Команди

```
/maniac start [маньяк]
/maniac stop
/maniac phase <фаза>
/maniac status
/maniac lobby set
/maniac point add <вид> [id]
/maniac point list
/maniac point clear
```

Одна гілка на всі види точок, бо всі точки однієї форми
(`SpawnPoint`). Новий вид точки = нове значення в `SpawnPointKind`,
команда не змінюється.

⚠ Розмітка поки живе в пам'яті матчу. Збереження у конфіг світу —
наступний крок (див. `spawn/README.md`).
