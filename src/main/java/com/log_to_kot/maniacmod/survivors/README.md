# survivors/ — виживші

## Що тут

- **SurvivorRole** — абстрактний базовий клас ролі (хп, слоти
  інвентаря, підсвітка). Зараз один тип (`DefaultSurvivorRole`),
  структура готова до додавання інших ролей.
- **SurvivorState** — ОКРЕМА машина станів (HEALTHY / BROKEN_LEG /
  CRAWLING / UNCONSCIOUS), незалежна від ролі. Один гравець за гру
  проходить кілька станів, лишаючись тією ж роллю.
- **SurvivorRegistry** — список усіх ролей.

## Роль vs Стан — у чому різниця

- **Роль** відповідає на питання "ХТО цей гравець" (постійна
  характеристика на весь матч: скільки в нього максимум хп,
  скільки слотів інвентаря).
- **Стан** відповідає на питання "ЩО з ним ЗАРАЗ" (змінюється
  протягом матчу: зараз здоровий, зараз повзе після поламаної
  ноги, зараз непритомний і чекає на порятунок).

Це навмисно два окремі класи, а не один — так система підняття
непритомного гравця чи лагодження ноги Шиною не залежить від
того, яка роль у постраждалого, і навпаки: додавання нової ролі
не вимагає переписувати логіку станів.

## v3 → v4

v3 `game/SurvivorData.java` мав спрощену модель (`lives` 1-3 і
прапор `bound`). Презентація "Виживші" описує набагато детальнішу
цільову систему (хп 100, стаміна, поламана нога тощо) — тому
`survivors/` тут ширший за прямий 1:1 перенос: базові класи вже
відповідають цільовій системі, а не поточному v3-коду. Точні числа
(швидкість витрати стаміни, час підняття непритомного) позначені
TODO — уточнити при перенесенні реальної логіки.
