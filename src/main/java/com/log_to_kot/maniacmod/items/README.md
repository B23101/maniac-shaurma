# items/ — предмети гри

## Що тут

- **ItemArchetype** — абстрактний базовий клас `extends Item`.
  На відміну від `ManiacArchetype`/`TrapArchetype` (окремі
  data-класи), тут архетип ОДНОЧАСНО і статистична картка, і
  реальний Forge `Item` — бо предмет фізично мусить бути `Item`,
  щоб `ModItems.ITEMS.register("id", XxxItem::new)` працював.
- **MedkitItem** — приклад мігрованого предмета (Аптечка), логіка
  перенесена 1:1 з v3 `items/ItemImplementations.java`.

## Спільна логіка (в ItemArchetype, не в кожному предметі)

- Кулдаун між використаннями (`cooldownTicks`).
- Ліміт використань за гру (`maxUsesPerGame`, -1 = без ліміту).
- `resetUsageTracking()` — виклик з `ManiacGameManager.resetGame()`
  на початку нової гри.

Підклас реалізує ЛИШЕ `onUse(player, stack)` — конкретний ефект.
Перевірку "чи готовий кулдаун" / "чи лишились використання"
робить `ItemArchetype.use(...)` один раз для всіх предметів.

таблиці, `onUse(...)` переноситься з відповідного класу в v3
`items/ItemImplementations.java`.

## Предмети маньяка (зброя, пастки-в-руці)

Зброя маньяків (конкретні `...KnifeItem`, `...TentacleItem`) і
предмети-пастки (`BearTrapItem` тощо, що ставляться ПКМ по блоку) —
теж `ItemArchetype`-підкласи, але концептуально пов'язані з
`maniacs/`/`traps/` (там задається сама механіка пастки/зброї,
тут лише "предмет у руці, яким її розміщують/атакують"). Уникайте
дублювання: `BearTrapItem.useOn(...)` викликає
`TrapRegistry.get("bear_trap")`, а не копіює логіку пастки в себе.
