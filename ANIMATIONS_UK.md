# Анімації тіла гравця — як створити (PlayerLib)

Інструкція для того, хто малює анімації. Код **уже готовий**: він реєструє
три пози й запускає їх у потрібні моменти. Не вистачає лише самих файлів
`.json` — їх треба створити в `src/main/resources/assets/maniacmod/player_animations/`.

Нижче — усе, що потрібно знати, щоб намалювати їх правильно з першого разу.

---

## 0. Два різні формати — не сплутати

У проєкті є **дві** абсолютно різні системи анімацій. Файли схожі за
назвою, і їх легко переплутати:

| Тека | Формат | Для чого |
|---|---|---|
| `assets/maniacmod/animations/entity/*.animation.json` | **GeckoLib** | geo-моделі **сутностей**: капкан, генератор, кріплення дроту, дріт |
| `assets/maniacmod/player_animations/*.json` | **PlayerAnimator (PAL)** | **тіло гравця** — усе, що описано нижче |

Ця інструкція — **тільки про другу теку**. Анімація на тіло гравця не має
нічого спільного з GeckoLib і не читається звідти.

---

## 1. Три файли, які треба створити

| Файл | Ім'я дії в коді | Шар | Коли грає |
|---|---|---|---|
| `player_animations/downed_lie.json` | `maniacmod:downed_lie` | `DEATH_LIE` (1100) | гравець впав і лежить/повзе (`CRAWLING` або `UNCONSCIOUS`) |
| `player_animations/generator_repair.json` | `maniacmod:generator_repair` | `ITEM_ACTION` (700) | тримає Shift+ПКМ на генераторі, стадія ремонту |
| `player_animations/generator_refuel.json` | `maniacmod:generator_refuel` | `ITEM_ACTION` (700) | тримає Shift+ПКМ на генераторі з каністрою, стадія заливу |

**Ім'я анімації всередині файлу мусить бути `animation.<ім'я файлу>`.**
Наприклад, у `downed_lie.json` ключ рівно `animation.downed_lie`.
Рушій прибирає префікс `animation.` і залишає `downed_lie`. Якщо ключ не
збігається з ім'ям файлу — поза **не завантажиться взагалі** (у лог
гри впаде `Не вдалось завантажити позу ...`).

Зразок уже робочого файлу в проєкті — `player_animations/flashlight_idle.json`.
**Найпростіший шлях: скопіювати його й перемалювати.** Тоді гарантовано
вийде правильний формат.

## 2. Структура файлу

```json
{
  "format_version": "1.8.0",
  "animations": {
    "animation.<ім'я файлу>": {
      "loop": true,
      "animation_length": 0.8,
      "bones": {
        "<кістка>": {
          "rotation": {
            "0.0": [-60, 0, 0],
            "0.4": [-80, 0, 0],
            "0.8": [-60, 0, 0]
          },
          "position": {
            "0.0": [0, 0, 0],
            "0.8": [0, 1, 0]
          }
        }
      }
    }
  }
}
```

Що означає кожне поле:

* **`loop`**
  * `true` — **HOLD**: крутиться циклічно, поки код сам не зупинить. Саме
    `true` потрібне для всіх трьох наших анімацій (лежання й робота
    тривають, доки триває стан).
  * `false` — **ONE_SHOT**: рушій сам завершить її по кінці кліпа. Для
    цих трьох **не підходить** — робота над генератором триває довільно
    довго, і одноразовий кліп просто завмер би на кінці.
* **`animation_length`** — довжина кліпа в **секундах** (не в тіках).
  Один тік = `1/20` секунди, тобто `0.8` = 16 тіків.
* **`bones.<кістка>.rotation`** — обертання у **градусах**, порядок
  `[x, y, z]`. Не пиши значення більше за ±180, воно загорнеться
  (рушій читає кути як ±π).
* **`bones.<кістка>.position`** — зсув у **«пікселях»**, де `16` = один
  блок (як у Blockbench). Потрібен переважно для `rightItem`/`leftItem`.
* Ключі часу — **рядки** (`"0.0"`, `"0.4"`), а не числа.

Доступні кістки гравця:

| Кістка | Що рухає |
|---|---|
| `head` | голова |
| `torso` | **тільки корпус** (нахил під час ремонту) |
| `body` | **усе тіло** одразу (синтетична) |
| `rightArm`, `leftArm` | руки |
| `rightLeg`, `leftLeg` | ноги |
| `rightItem`, `leftItem` | предмет у відповідній руці (каністра, лом) |

> Якщо написати ім'я кістки з помилкою (`right_arm`, `armRight`), гра не
> впаде — просто **нічого не станеться** з цією кісткою. Тобто «не
> працює хіба одна рука» = майже завжди одрук в імені.

## 3. Головне питання: чи можна анімувати **лише руки**?

**Так, і це вбудована властивість рушія, а не хак.**

Працює це так:

* Кожна поза живе у своєму **шарі**. Шар накладається поверх нижчих шарів.
* **Кістка без keyframe-ів — прозора**: вона не чіпається взагалі, і
  залишається те, що дала ванільна модель або нижчий шар.
* Кістка, у якої keyframe-и **є**, повністю **замінює** цю кістку.

З цього випливає рецепт для «рухи лише руками»:

1. У `bones` описати **тільки** `rightArm` / `leftArm` (та
   `rightItem` / `leftItem`, якщо треба посунути предмет у руці).
2. **Не писати взагалі** `head`, `torso`, `body`, `rightLeg`, `leftLeg`.

Тоді ноги й корпус живуть своїм життям (ванільна ходьба, біг,
присідання), а руки рухаються за твоєю анімацією. Приклад:

```json
"bones": {
  "rightArm": {
    "rotation": {
      "0.0": [-105, -12, 8],
      "0.4": [-70,  -12, 8],
      "0.8": [-105, -12, 8]
    }
  },
  "leftArm": {
    "rotation": {
      "0.0": [-95, 10, -8],
      "0.4": [-60, 10, -8],
      "0.8": [-95, 10, -8]
    }
  }
}
```

### Пріоритет шарів (якщо треба перекрити чуже)

| Шар | Пріоритет | Що там зараз |
|---|---|---|
| `DEATH_LIE` | 1100 (найвищий) | лежача поза виживого |
| `ITEM_ACTION` | 700 | ліхтарик, аптечка, **ремонт і залив генератора** |
| `CUSTOM` | 500 | вільний |
| `LOCOMOTION_OVERRIDE` | 100 (найнижчий) | кастомна хода — вмикається лише явно |

Вищий шар перекриває нижчий **тільки на тих кістках, де в нього є дані**.
Тому поза рук на `ITEM_ACTION` не заважає ногам, але й не перебиває лежання
(воно на вищому шарі).

### Динамічна маска (якщо треба залежно від стану)

Якщо кут має залежати від чогось ігрового (наприклад, нахил за кутом
погляду), є `BoneAdjustment`: повертаєш `Optional.empty()` — кістка
прозора, тобто **повернення порожнього значення і Є маска**:

```java
PlayerPoseController.applyBoneAdjustment(player, PoseLayerId.ITEM_ACTION,
    bone -> switch (bone) {
        case "rightArm", "leftArm" -> Optional.of(BoneAdjustment.Part.pitchDegrees(player.getXRot() / 2));
        default -> Optional.empty();   // усі інші кістки не чіпаємо
    });
```

Правка **додається** до keyframe-ів (а не замінює їх) і скидається сама,
коли поза завершується.

## 4. Три пози — що саме малювати

### 4.1. `downed_lie.json` — лежачий виживий

**Контекст, який легко забути:** тіло гравця у цьому стані примусово
стоїть у ванільній позі **лежання** (`Pose.SWIMMING`): уся модель уже
повернута приблизно на 90° і лежить горизонтально, а хітбокс стиснутий до
`0.6 × 0.6`. Це робить код (`MixinPlayerDownedPose`) — **хітбокс і позу
тіла вже зроблено, тобі лишається тільки `.json`**.

Тобто твоя анімація малюється **у системі координат уже лежачого тіла**:
«вгору» для тебе — це вгору від землі, а «вперед» — напрямок повзання.
Через це кути з першого разу майже завжди виходять «не в той бік» —
підбирай знак `x` у грі, а не на папері.

Задум пози: людина лежить на животі й підтягується на ліктях.

```json
{
  "format_version": "1.8.0",
  "animations": {
    "animation.downed_lie": {
      "loop": true,
      "animation_length": 1.6,
      "bones": {
        "torso": {
          "rotation": {
            "0.0": [-10, 0, 0],
            "0.8": [-14, 0, 0],
            "1.6": [-10, 0, 0]
          }
        },
        "head": {
          "rotation": {
            "0.0": [-35, 0, 0],
            "0.8": [-28, 0, 0],
            "1.6": [-35, 0, 0]
          }
        },
        "rightArm": {
          "rotation": {
            "0.0": [-120, -10, 0],
            "0.8": [-80, -10, 0],
            "1.6": [-120, -10, 0]
          }
        },
        "leftArm": {
          "rotation": {
            "0.0": [-70, 0, 0],
            "0.8": [-110, 0, 0],
            "1.6": [-70, 0, 0]
          }
        },
        "rightLeg": { "rotation": { "0.0": [-10, 0, 0], "0.8": [-25, 0, 0], "1.6": [-10, 0, 0] } },
        "leftLeg":  { "rotation": { "0.0": [-25, 0, 0], "0.8": [-10, 0, 0], "1.6": [-25, 0, 0] } }
      }
    }
  }
}
```

Лікті мають бути **перед грудьми, а не під тілом** — інакше руки «проходять
крізь» землю, бо хітбокс лежачого дуже низький.

### 4.2. `generator_repair.json` — ремонт генератора

Умови задає гра, і це спрощує роботу:

* Гравець **обов'язково тримає Shift** (це його частина умови взаємодії),
  тож ванільна поза присідання вже застосована — **ноги малювати не
  треба**, присідання виглядає правильно саме собою.
* Рух і камера на час роботи заблоковані, тобто тіло нерухоме: анімація
  не мусить виглядати добре «на ходу».
* Рецепт: **рухи лише руками** + легкий нахил корпусу (`torso`).

```json
{
  "format_version": "1.8.0",
  "animations": {
    "animation.generator_repair": {
      "loop": true,
      "animation_length": 0.8,
      "bones": {
        "torso": {
          "rotation": { "0.0": [16, 0, 0], "0.4": [22, 0, 0], "0.8": [16, 0, 0] }
        },
        "rightArm": {
          "rotation": {
            "0.0": [-105, -14,  8],
            "0.4": [ -72, -14,  8],
            "0.8": [-105, -14,  8]
          }
        },
        "leftArm": {
          "rotation": {
            "0.0": [-92, 12, -8],
            "0.4": [-62, 12, -8],
            "0.8": [-92, 12, -8]
          }
        }
      }
    }
  }
}
```

Руки в цьому прикладі рухаються **в протифазі** (одна вгору, друга вниз) —
виглядає як справжня робота інструментом, а не як махання двома руками
одночасно.

### 4.3. `generator_refuel.json` — залив бензину

Те саме, але з каністрою в руках. Особливість: **предмет намальовано не
окремою GeckoLib-моделлю, а через кістки `rightItem`/`leftItem`** — тому
«нахилити каністру» означає написати keyframe-и саме для них.

```json
{
  "format_version": "1.8.0",
  "animations": {
    "animation.generator_refuel": {
      "loop": true,
      "animation_length": 1.0,
      "bones": {
        "torso": {
          "rotation": { "0.0": [12, 0, 0], "0.5": [18, 0, 0], "1.0": [12, 0, 0] }
        },
        "rightArm": {
          "rotation": {
            "0.0": [-70, -18,  6],
            "0.5": [-95, -18, 14],
            "1.0": [-70, -18,  6]
          }
        },
        "rightItem": {
          "position": {
            "0.0": [0, 0, 0],
            "0.5": [0, 1, 2],
            "1.0": [0, 0, 0]
          },
          "rotation": {
            "0.0": [ 0, 0,   0],
            "0.5": [ 0, 0, -35],
            "1.0": [ 0, 0,   0]
          }
        }
      }
    }
  }
}
```

## 5. Як перевірити в грі

1. Поклади файли в
   `maniac_shaurma/src/main/resources/assets/maniacmod/player_animations/`.
2. Запусти гру. Після зміни `.json` **не обов'язково перезапускатись**:
   `F3 + T` перезавантажує ресурси, і кеш анімацій скидається автоматично.
3. Як побачити кожну позу:
   * **лежання** — отримати травму так, щоб стан став `CRAWLING`
     (упасти з висоти з поламаною ногою / довести здоров'я до 0);
   * **ремонт** — підійти до генератора, затиснути **Shift + ПКМ**;
   * **залив** — те саме, але з **каністрою в руці** та на стадії заливу.

Що означає «нічого не відбувається»:

| Симптом | Причина |
|---|---|
| Нічого не рухається, у лозі `Не вдалось завантажити позу maniacmod:...` | ім'я файлу не збігається з ім'ям дії (див. таблицю в п. 1) або ключ усередині не `animation.<ім'я файлу>` |
| Анімація програлась один раз і завмерла | стоїть `"loop": false` — для цих трьох потрібне `true` |
| Рухається лише одна рука | одрук в імені другої кістки |
| Рука смикається ривками | занадто довгий кліп із малою кількістю keyframe-ів; додай проміжні кадри |
| Лежачий виглядає «скрученим» | кути малювались для стоячого тіла: модель уже повернута на 90° (див. 4.1) |

## 6. Де це в коді (щоб знайти й підправити)

| Що | Файл |
|---|---|
| Реєстрація всіх трьох дій | `client/ClientSetup.java`, метод `onClientSetup` |
| Лежача поза: коли старт/стоп | `client/DownedPoseAnimation.java` |
| Поза рук: коли старт/стоп | `client/GeneratorWorkAnimation.java` |
| Назви дій і fade | константи `LIE_ACTION` / `REPAIR_ACTION` / `REFUEL_ACTION` у тих самих класах |
| Шари й пріоритети | `shaurma-lib`: `dev.shaurmalib.common.playeranim.PoseLayerId` |
| Хто повідомляє клієнтам «хто працює» | `net/s2c/notify/GeneratorInteractionPacket.java` |

**Fade** (плавна поява/згасання) задається **в коді**, не у файлі:
`PoseSource.hold(...).withFade(4, 6)` — 4 тіки на появу, 6 на згасання.
Хочеш інакше — правити там, у `registerActions()`.

## 7. Короткий чек-ліст перед тим, як кидати файли

- [ ] Ім'я файлу точно збігається з назвою в таблиці п. 1.
- [ ] Ключ усередині — `animation.<ім'я файлу>`.
- [ ] `"loop": true`.
- [ ] Кути — градуси, у межах `±180`.
- [ ] Ключі часу — рядки (`"0.0"`).
- [ ] Не потрібні кістки **не згадані взагалі** (а не записані нулями).
- [ ] `F3 + T` після правок.
